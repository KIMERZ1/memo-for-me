# 설계서: Memo4Me

macOS 메뉴바 메모지 앱 Memo4Me(저장소 `memo-for-me`)의 설계입니다. 구현된 상태를 기준으로 합니다. 이 앱의 메모를 Notion으로 올리는 `sticky`는 별도 저장소(`notion-memo-agent`)의 `docs/DESIGN.md`에 있습니다.

## 1. 의도와 원칙

일정(시험, 계절학기 등)과 API 키 같은 짧은 메모를 **데스크톱의 특정 Space에 실제로 붙여 놓고** 씁니다.

- **앱은 Notion, Claude, `sticky`를 모릅니다.** 메모를 규격 폴더에 파일로 남기기만 합니다. 샌드박스 앱은 다른 프로그램을 실행할 수도 없습니다.
- **연결은 파일로만** 합니다. 접점은 4장의 "메모 폴더 규격" 하나입니다.
- Apple Stickies와 비슷한 사용 흐름을 따릅니다.

**하지 않는 것**: 앱 안에서 Notion API 호출이나 토큰 보관, iCloud/iOS/협업, 보안 메모의 외부 반영, 앱스토어 배포(샌드박스는 폴더 접근과 키체인 때문에 유지).

**실패로 보는 것**
- 앱을 켤 때마다 독이 튀어나오거나 화면이 전환됨.
- 메모가 모든 Space에 따라다님.
- 창을 움직일 때마다 `.md`가 바뀌어 가짜 변경이 생김.
- 보안 메모의 평문이 디스크나 변경 기록에 남음.

## 2. 사용자 요구

| 영역 | 내용 |
|---|---|
| 모양 | 기본 색 노랑/파랑, 사용자 이미지를 배경으로 지정 가능. 둥근 모서리, 제목 표시줄 없음 |
| 편집 | 글자 크기·굵게·기울임·밑줄·취소선은 **선택한 글자에만** 적용. 서식 바는 선택 후 마우스를 놓으면 나타남 |
| 크기 조절 | 모서리 4개와 변 4개 핸들(PPT 방식) |
| 상단 바 | 왼쪽부터 닫기, 고정, 최상단 고정, 색, 삭제 / 가운데 이름 입력칸 / 오른쪽 `+` |
| 메뉴바 | 메모지 추가, 메모지 목록 ▸, 설정…, 종료. 아이콘을 눌러도 창이 튀어나오거나 화면이 전환되지 않음 |
| Space | 메모지는 만들어진 Space에만 나타나고 그 위치에 붙어 있음 |
| 재실행 | 열려 있던 메모지를 모두 복원(위치, 크기, 색) |
| 단축키 | `⌘N` 새 메모, `⌘W` 닫기(삭제 아님), `⌘B/I/U`, `⌘+/-` 크기, `⌘⇧X` 취소선, 편집 단축키 |
| 설정 | 저장 폴더 지정, 현재 경로 표시, Finder에서 보기, 경로 복사 |

## 3. 구현

Swift 6, macOS 14+. AppKit 중심(창·텍스트 편집), SwiftUI는 설정 화면에만 사용합니다. 핵심 로직은 UI와 분리된 `Sources/StickyCore`(SwiftPM)에 두어 단위 테스트합니다.

- **창**: 비활성(non-activating) `NSPanel`. 앱이 활성화되지 않아도 메모 위에서 입력할 수 있고 다른 앱의 앞순서를 빼앗지 않습니다. 공식 API만 사용합니다(`collectionBehavior` 기본값으로 Space에 붙음, 비공개 API 금지).
- **서식 저장**: Markdown과 최소한의 인라인 HTML입니다. `**굵게**`, `*기울임*`(한글에서도 보이도록 화면에서는 `obliqueness` 기울임), `~~취소선~~`, `<u>밑줄</u>`, `<span style="font-size:15pt">`. 폰트 선택은 없고 시스템 글꼴 하나만 씁니다.
- **단축키**: 앱에 편집 메뉴가 없어서 패널이 직접 처리합니다. **글자가 아니라 물리 키 번호**로 판별해서 한글 입력 상태(`⌘C`가 `ㅊ`로 보고됨)에서도 동작합니다. 이름칸에 포커스가 있으면 이름칸이 편집 단축키를 받습니다.
- **커서와 호버**: 앱이 비활성일 때도 커서 모양이 맞도록 단일 소유자가 커서를 관리하고, 호버 효과는 AppKit 추적 영역으로 처리합니다(SwiftUI `onHover`는 비활성 패널에서 불안정).
- **상단 바와 서식 바**: AppKit으로 구현했습니다. 이름칸은 양옆에 24pt씩 여백을 두어 그 부분을 잡고 창을 끌 수 있습니다.
- **Space**: 공식 API만 사용하므로 재실행 후 같은 Space로 돌아오는지는 환경에 따라 다릅니다. 안 되면 현재 Space에 띄웁니다.

## 4. 저장과 메모 폴더 규격

| 대상 | 위치 | 내용 |
|---|---|---|
| 일반 메모 | 사용자가 지정한 폴더 | 메모 1개 = `<제목>-<짧은id>.md` (앞머리 `id`, `created`, `type`, 선택 `name`) |
| 변경 기록 | 같은 폴더 `changes.jsonl` | 생성/수정/삭제를 한 줄씩 추가(`v`, `ts`, `event`, `id`, `file`, `title`), 본문 없음 |
| 규격 표시 | 같은 폴더 `sticky-source.json` | 이 폴더가 규격을 지킨다는 표시 |
| 경로 안내 | 앱 컨테이너 `notes-folder.txt` | 폴더의 실제 경로 한 줄 |
| 창 상태 | 앱 컨테이너 `state.json` | 위치, 크기, 색, 배경, 고정 여부, 열림 여부 |
| 배경 이미지 | 앱 컨테이너 | 원본 이동·삭제에 영향받지 않게 복사 |
| 보안 메모 | 앱 컨테이너 `.enc` | 암호화, 사용자 폴더에는 없음 |

- 위치·크기·색은 `.md`에 넣지 않습니다(창을 움직였다고 가짜 변경이 생기지 않도록).
- 저장은 입력 후 약 0.5~1초 뒤에 원자적으로 씁니다. 내용이 실제로 바뀐 저장만 기록합니다.
- 폴더를 바꾸면 기존 메모와 기록을 옮길지 묻고 북마크를 갱신합니다. 폴더나 권한이 사라져도 창은 유지하고 안내만 합니다(데이터 손실 금지).
- 폴더 접근은 사용자가 고른 폴더의 보안 범위 북마크로만 합니다. 샌드박스 앱은 북마크로만 경로를 기억하기 때문에 `notes-folder.txt`로 실제 경로를 따로 남깁니다.
- 외부에서 `.md`가 수정되면 앱이 덮어쓰지 않고 외부 변경을 보존합니다.
- 규격 전체와 다른 메모장 앱을 붙일 때의 체크리스트는 `sticky` 저장소의 `docs/NOTE-APP-INTEGRATION-GUIDE.md`(Notes Source Contract v1)에 있습니다. 이 앱은 그 규격의 기준 구현(L3)입니다.

## 5. 보안 메모

- **암호화**: AES-256-GCM(CryptoKit). 키는 키체인에 저장합니다(기기 한정, 분실하면 복구 불가).
- **잠금**: 열 때 Touch ID/시스템 암호(`LocalAuthentication`). 인증이 실패하거나 사용할 수 없으면 열리지 않습니다(fail-closed). 앱을 켤 때가 아니라 사용자가 열 때만 요구합니다.
- **노출 차단**: 보안 메모는 폴더에도 `changes.jsonl`에도 나타나지 않습니다. 잠긴 동안은 복사·편집 단축키도 막고, 목록에는 번호로만 표시하며, 빨간 테두리로 구분합니다.
- 그래서 보안 메모는 **구조적으로 외부 프로그램에 읽힐 수 없습니다.**
- 일반 메모의 **제목**은 변경 기록에 평문으로 남으므로 제목에 비밀을 쓰지 않도록 안내합니다.

## 6. 설계 결정

| 결정 | 검토한 대안 | 이유 |
|---|---|---|
| AppKit 중심 하이브리드 | SwiftUI 중심, Electron/Tauri | 부분 서식, 테두리 없는 창, 리사이즈, Space 동작이 AppKit에서 가장 안정적. Electron은 Space 제어와 메뉴바 전용에 불리 |
| 앱은 파일로만 연결 | 앱이 Notion API 직접 호출 | 샌드박스 앱이 다른 프로그램을 실행할 수 없고, 토큰 보관과 보안 메모 경계가 복잡해짐 |
| Space 복원은 공식 API만 | 비공개 CGS 함수 | 비공개 API는 쓰지 않음. 복원이 안 되면 현재 Space에 띄움 |
| 보안 메모는 앱 컨테이너 안에만 | 사용자 폴더에 암호문 저장 | 사용자 폴더는 외부 프로그램이 읽을 수 있으므로 평문도 암호문도 두지 않음 |

## 7. 검증 현황

- StickyCore 단위 테스트 76개 통과.
- **확인하지 못한 것**: 재실행 후 같은 Space로 돌아오는지는 사용자 환경에서의 확인 결과가 없습니다.
